Providers

Your keys, and what each provider can actually do.

Keys are held in this browser only — localStorage, never sent anywhere by this page and never written into the repository. In a desktop build, swap the storage adapter in app.js for the OS keychain.

Missing one? Add it to reference/providers.json — it shows up here and in automatically. That file is the single source of truth for both tabs.

Capability data goes stale. Providers ship features constantly. Last reviewed —; treat any row older than a month or so as a prompt to re-check the provider's docs (linked in every row) rather than as current fact.

✓ supported · · not supported · ? unknown, needs probing. Aggregators report the ceiling across the models they route to — an individual model may do less.

Adding or updating a provider
  1. Edit reference/providers.json. One object per provider: id, name, category, keyUrl, docsUrl, envVar, baseUrl, and a capabilities block.
  2. Use null for a capability you have not checked. It renders as ? — an honest gap beats a guess that reads as fact.
  3. Bump lastReviewed when you re-verify a row.
  4. Run scripts/check-links.py. CI runs it too, so a console URL that moves fails the build instead of quietly 404-ing for users.
